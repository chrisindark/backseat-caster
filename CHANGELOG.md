## [Unreleased]

### Added
- **Branded intro & outro cards (Phase 10.5):** every render can now open with a channel card and close with a `SUBSCRIBE` card, so a clip looks branded without any editor work.
  - Cards are drawn locally with Pillow ([`app/rendering/branding.py`](app/rendering/branding.py)) at each output's exact pixel size and fed back into the *same* single FFmpeg pass as looped still inputs, so branding costs no second encode generation. `drawtext` was deliberately avoided: it needs an FFmpeg built with libfreetype (absent from the Homebrew macOS build and from slim images) plus a resolvable font file.
  - `build_branding_plan` rasterises one intro/outro pair per requested format, `build_concat_filter` wraps each format as `[intro][main][outro]concat=n=N:v=1:a=0`, and `build_branding_audio_filter` delays the clip audio by the intro then trims/pads it to the composed length so lip-sync stays correct behind both cards.
  - `RenderResult` gains `total_duration_seconds`, `branding_applied`, `branding_intro_seconds` and `branding_outro_seconds`; `manifest.json` records the applied branding (copy, lengths, padding, composed duration) and `outputs.*.duration` now reports the branded length. Card PNGs are deleted after the encode.
  - Stored on the channel profile (`branding_*` columns, Alembic revision `b4d8e2f6a1c3`) and edited at `/channel` → *Intro & Outro Cards*: master toggle, per-bookend toggles, headline/subtitle copy, intro/outro lengths and accent/background colours. `BRANDING_*` settings now seed a fresh profile and stand in for any unset column, so `.env`-only installs behave exactly as before. Applies to every manual and auto-staged render. New dependency: `pillow`; the backend image now installs `fonts-dejavu-core`.
  - **Clip length ceiling (Phase 10.5 follow-up):** every render is now bounded by a composed-duration ceiling (clip + bookends), default 90 s and editable as `max_clip_seconds` on the profile (`MAX_CLIP_SECONDS` seeds it, Alembic revision `c7f1a9d3e5b2`). Auto-stage clamps candidates to the ceiling; manual renders over it are rejected with a clear message instead of silently producing a non-Short. 60 / 72 / 88 s are soft labels inside the ceiling and never block an upload. `manifest.json` records the budget (`duration_budget`) and tier.
  - **CTA voiceover (TTS + bell chime):** optional neural voiceover + bell chime mixed into the outro of every render when enabled, synthesised with `edge-tts` (new dependency) and cached by an MD5 key under `data/channel/tts_cache/`; degrades to silence offline. Configured at `/channel` → *CTA Voiceover* (`cta_*` columns, Alembic `d8a2c4e6f1b3`). In-video overlay mode is planned but not yet rendered.
- **Channel brand consistency (Tier 3):** a singleton `channel_profiles` row now stores the creator's channel-wide defaults in SQLite instead of `.env`: watermark/logo overlay (position, opacity, scale, margin), default framing preset, default quality preset, title template (`{title}`, `{channel}`, `{hero}`, `{game}`, `{event}`, `{date}`, `{clip_id}`), pinned hashtags, default privacy, daily upload slots and schedule timezone.
  - New `app/routers/channel.py` endpoints: `GET/PUT /api/v1/channel/profile`, `POST/DELETE /api/v1/channel/watermark`, and `GET /api/v1/channel/watermark` for preview. Logos are stored under `data/channel/`.
  - The FFmpeg single-pass engine composites the watermark into every requested format (landscape, vertical blur and all crop presets) before branded bookends, scaling the logo relative to each output's width. `RenderJob` gains `quality_preset`, and manifests record the applied quality/watermark.
  - Render creation, auto-stage and upload now resolve framing/quality/privacy/slots from the channel profile; title templates and pinned hashtags are applied to auto-generated and regenerated copy. The new `/channel` UI manages the profile and Studio/batch staging preseed the channel's framing preset.
  - Alembic revision `e1a2b3c4d5e6` adds `channel_profiles` and `render_jobs.quality_preset`.
- **Zero-input ingest (Phase 10):** two features that remove the remaining manual steps between "recording exists" and "clips are staged".
  - **Auto-mine on ingest (`AUTO_MINE_ON_INGEST`):** a completed `yt-dlp` download or OBS upload now dispatches highlight detection automatically, which in turn auto-stages the top candidates with metadata and `publishAt` slots. Implemented as a thin, non-fatal wrapper over `HighlightService.detect_highlights` (`app/services/auto_mine.py`), so run records, status transitions and the Celery/`BackgroundTasks` fallback are unchanged. `AUTO_MINE_GAME` pins a detector profile, `AUTO_MINE_MIN_SCORE` sets the threshold and `AUTO_MINE_AUTO_RENDER_TOP_N` overrides the auto-stage count. Videos already mined are skipped, and a mining failure never fails the ingest.
  - **OBS watch folder (`WATCH_DIR`):** point the app at the directory OBS writes into and finished recordings are copied (or moved with `WATCH_DELETE_AFTER_INGEST`) into `data/downloads`, probed, thumbnailed, catalogued and auto-mined (`app/services/watch_folder.py`). A stability gate (`WATCH_STABILITY_SECONDS`) prevents ingesting a file OBS is still writing, and a new `watch_ingests` table de-duplicates takes by `size:mtime` fingerprint while still re-ingesting a filename OBS overwrites. Poll via Celery beat (`WATCH_POLL_INTERVAL_MINUTES`) or on demand.
  - New endpoints: `GET /api/v1/videos/watch/status`, `POST /api/v1/videos/watch/scan` (supports `dry_run=true`). Settings manageable from the setup wizard and persisted to `data/settings.json`; setup diagnostics gain an optional *Zero-Click Ingest* check. Alembic revision `d7e3b9a1c2f4` adds the ledger table.
- **Autonomous auto-stage & scheduler pipeline (Phase 8):** highlight detection can now auto-render the top N candidates as vertical Shorts (`AUTO_STAGE_*` settings or `auto_render_top_n` per request), generate Gemini-tailored title/description/tags with a deterministic fallback (`app/services/llm_metadata.py`), and assign staggered native YouTube `publishAt` slots (`app/services/auto_stage.py`).
  - New `RenderJob` columns `auto_staged`, `highlight_candidate_id`, `scheduled_publish_at`, plus a `youtube_quota_usage` table and Alembic migration.
  - Quota accounting service (`app/services/youtube_quota.py`) tracks the 10,000 unit/day YouTube budget with midnight-Pacific resets. Accounting is advisory — uploads are never blocked locally; an exhausted budget surfaces as YouTube's own `quotaExceeded` error and the UI warns before dispatching.
  - New endpoints: `GET /api/v1/youtube/quota`, `GET /api/v1/youtube/staging`, `POST /api/v1/youtube/staging/{clip_id}/schedule`, `POST /api/v1/youtube/staging/{clip_id}/publish-now`, `POST /api/v1/youtube/auto-stage`; uploads accept an explicit `publish_at`.
  - Renders UI gains an auto-staged banner, quota bar and review drawer with per-clip scheduling and 1-click publish (`ui/src/components/AutoStagePanel.tsx`).
  - **Metadata regeneration:** `POST /api/v1/renders/{clip_id}/regenerate-metadata` rewrites staged title/description/tags without re-rendering, with an explicit AI (`use_llm: true`) vs deterministic (`use_llm: false`) choice; the replaced copy is returned/stored as `previous_metadata` so both outputs can be compared. Exposed as an "AI copy" checkbox + Regenerate control in the auto-stage drawer and the Upload Queue modal, with a side-by-side *previous/current* comparison view. `GET /youtube/staging` now reports `llm_available`.
  - New dependencies: `google-genai`.
- **Storage cleanup & maintenance pipeline:** `POST /api/v1/videos/{video_id}/cleanup` reclaims disk per video (source VOD and/or already-uploaded render folders), and `POST /api/v1/renders/cleanup-uploaded` plus `POST /api/v1/renders/auto-pipeline` do it across the catalog (`app/services/auto_pipeline.py`). Uploaded render folders are deleted while `RenderJob` rows and YouTube links are retained; source VODs are only removed when every completed render is uploaded. The same sweep stages each downloaded video's next `AUTO_STAGE_TOP_N` highlights, so repeated runs consume the next-best candidates instead of stopping at already-staged ones.
  - Optional Celery beat scheduling via `AUTO_PIPELINE_INTERVAL_MINUTES`, `AUTO_CLEANUP_UPLOADED_RENDERS` and `AUTO_CLEANUP_VOD`; Compose gains a `celery_beat` service.
- **Deep visual event extraction (Phase 3):** structured killfeed row parser with friendly/enemy colour inference and attributed multi-kill chains (`killfeed.py`), ultimate meter OCR with circular gauge fallback, ready-flash detection, cast detection and post-cast kill correlation (`ultimate_meter.py`), plus hero portrait and ability cooldown/activation template matching (`hero_identifier.py`) orchestrated through `deep_visuals.py`.
  - New HUD regions: `hero_portrait`, `ability_row`; new `HERO_TEMPLATES_DIR` (`./data/hero_templates`) for creator-supplied `<game>/heroes` and `<game>/abilities` templates. Identification degrades to a no-op when templates are absent.
  - Candidates now carry `hero_name`, `multi_kill_chain`, `killfeed_chain`, `ultimate_casts` and `abilities_used`, with score boosts for killfeed-corroborated and ultimate-payoff clips.
- Documentation set: root guides (ARCHITECTURE, CONFIGURATION, DEVELOPMENT, API_REFERENCE, SECURITY, ROADMAP, RELEASES, CONTRIBUTING), `docs/` deep dives, `docs/adr/` decision records, and `examples/`.

### Fixed
- **YouTube upload failures were misreported as API quota exhaustion.** Google's `HttpError` payload is now parsed into a structured error, distinguishing `quotaExceeded` (project Data API budget, resets at Pacific midnight) from channel-level `uploadLimitExceeded` (usually clears within 24h). Sync uploads return a friendly `429` message with `error_code`/`retry_at`; staging and auto-stage cards show the persisted error instead of a raw `HttpError` string. The local quota counter now charges units only after a successful upload, records failed attempts separately, and persists an active block reason/expiry. Alembic revision `f8b1c2d3e4a5` adds the tracking columns.
- **`alembic upgrade head` failed on a fresh database.** Revision `86c5d2b7b10a` re-created four indexes that `8e54d5fa3f7d` had already created when building `render_jobs`, aborting the chain with `index ix_render_jobs_clip_id already exists`. This broke every clean install, including the Docker startup command (`alembic upgrade head && uvicorn`). The duplicate `create_index`/`drop_index` calls were removed; databases that already migrated are unaffected.
- **`data/settings.json` was not gitignored.** It persists in-app settings including a plaintext `llm_api_key`, so it is now excluded along with `data/celerybeat-schedule`.

## [0.1.0] — Initial operational release

### Added
- **Local rendering engine (Phase 1):** 16:9 landscape master, 9:16 vertical outputs (`vertical_blur`, preset crops `third_person` / `cinematic` / `direct_crop`), Lanczos scaling, quality presets (`high`, `compact`, `archive`), automatic `h264_videotoolbox` / `libx264` encoder selection, standalone CLI (`app/rendering/cli.py`), probe & validation suites.
- **Audio pipeline:** sidechain ducking for narration voiceovers, peak limiting, EBU R128 `loudnorm` targeting -14 LUFS.
- **Creator studio UI (Phase 6):** `/studio/[id]` timeline scrubbing, crop guide overlays, comparison player, `/renders` catalog with bulk delete, manifest viewer.
- **Ingestion (Phase 7 + Phase 2):** YouTube channel scraping & VOD download via `yt-dlp` (`/videos/sync`, `/videos/{id}/download`), drag-and-drop OBS upload (`/videos/upload`) with probe & thumbnail generation.
- **Highlight mining (Phase 2 + 2.5):** audio energy scanner, ROI extractor, color/OCR visual matcher with Marvel Rivals detector set, window clustering & scoring API/UI drawer; anti-false-positive hardening with 8x faster Stage 3, adaptive sampling, scoreboard rejection, persistence scoring.
- **Publishing (Phase 7):** Google OAuth 2.0 flow, upload staging queue, resumable YouTube Shorts publishing via YouTube Data API v3.
- **Worker engine (Infra):** Celery + Redis with automatic zero-config fallback to FastAPI `BackgroundTasks`; `is_celery_broker_online` health gating.
- **Platform:** FastAPI + Pydantic v2 routers under `/api/v1`, `BaseResponse[T]` envelope with global exception handlers, correlation-ID middleware + colored logging, SQLAlchemy 2.0 / SQLite / Alembic migrations, Docker Compose full stack (backend, worker, redis, frontend), pytest suite with synthetic media assets.
